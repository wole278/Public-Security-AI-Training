## 📖 第一部分：80% 直读自学区（00:00 - 00:45）

### 模块一：警务 AI 安全死线与“留壳去肉”脱敏法（12 分钟）

很多同志对 AI 既想用又怕用：**“我把案情或报表发给大模型，算不算违规一机两用？AI 胡编乱造法条害我办错案怎么办？”**  
请牢记以下**三条铁律**，只要按规矩操作，就能 100% 安全合规地借力 AI：

#### 1. 铁律一：内外网物理隔离，双轨分流作业
* **公安网 / 视频专网（内网端）**：只能使用市局/分局内网已部署的警务大模型，或在科信离线工作站本地部署的开源大模型（如通过 Ollama 运行的本地 Qwen / DeepSeek 模型）。**内网可以跑真实警务数据**。
* **政务外网 / 互联网端（外网端）**：使用公有大模型（DeepSeek、豆包、Kimi 等）时，**严禁上传任何 P3 级受限警务数据**（真实姓名、身份证号、手机号、真实车牌、银行卡号、未公开在侦案件细节、专网 IP 拓扑）。

#### 2. 铁律二：外网借力的两大合法神技——“留壳去肉法”与“表头代写法”
如果我们手头只有外网大模型，怎么处理内网的复杂工作？用下面两招：

| 技法名称 | 适用人群 | 核心操作口诀 | 错误作死操作（❌ 严禁） | 合规满分操作（✅ 推荐） |
| :--- | :--- | :--- | :--- | :--- |
| **第一招：留壳去肉脱敏法** | 一线民警（写预案、理笔录、改通报） | **“真名换代号，尾号打星号，地名缩片区，保留逻辑壳”** | 直接把含真名“王建国（31010419820512331X）、车牌沪A88991、住址XX路128弄3号201室”的受案材料粘进外网网页。 | 在本地用 Word 批量替换：`王建国 → 张某甲`、`身份证 → [身份证号A]`、`沪A88991 → [车牌号1]`、`XX路128弄 → [辖区A小区]`，让 AI 梳理完逻辑或生成文书后，再在本地替换回真实信息。 |
| **第二招：表头脱敏代写法** | 技术科/图侦/网安（洗数据、查流水、跑统计） | **“真表不出网，只发字段名；AI 写脚本，内网跑真数”** | 把包含 5 万条市民报警记录或嫌疑人银行流水的 Excel 直接上传给外网 AI 分析。 | **只复制 Excel 的第 1 行表头字段名 + 自己编造的 2 行假数据**发给外网 AI，让它写出一段 Python 或 Excel 宏代码；把代码复制回内网电脑，3 秒处理 5 万条真实数据！ |

#### 3. 铁律三：AI 只是“参谋辅警”，民警签字前必须过“三核查”
* **核查事实要素**：时间、地点、涉案金额是否与原卷/原表一致（防止 AI 自动脑补细节）。
* **核查法规引用**：凡 AI 引用的《刑法》《治安管理处罚法》《道路交通安全法》条文号，必须对照最新法条核实（或挂载本地法规知识库）。
* **核查逻辑闭环**：AI 给出的排堵方案或侦查方向仅作研判参考，最终决策权在指挥员与主办民警。

### 模块二：告别“一句话提问”——警务 R-C-T-F 万能公式（13 分钟）

为什么有的人觉得 AI 写出来的东西全是“正确的废话”？因为他们把 AI 当百度用，只输入了一句话。  
在警务实战中，只要套用 **`R-C-T-F` 四步指令公式**，AI 的输出质量会瞬间从“实习生水平”飙升到“十年老科长/资深工程师水平”：

```text
【R - Role 警种角色】：你现在是一名拥有10年经验的上海基层[交警中队长 / 治安支队研判员 / 公安科信Python高级工程师]...
【C - Context & Constraints 辖区背景与纪律约束】：当前面临[某具体场景/痛点]。严格遵守：1. 不编造未提供的事实；2. 符合《XX工作规范》；3. 语气客观、干练、去套话...
【T - Task & Data 核心任务与脱敏数据】：请基于以下提供的[脱敏数据/表头结构/现场情况]，完成[1. 原因剖析；2. 处置措施；3. 编写自动化脚本]...
【F - Format 输出格式】：请严格按照[Markdown 表格 / JSON 结构 / 公安标准预案四级目录 / 零依赖 Python3 代码]格式输出。
```

#### 🔍 直观对比：一句话提问 vs R-C-T-F 公式提问（直接看效果差距）

  > “帮我写一份商业街夜市治安和交通管理的方案。”
* **❌ 菜鸟提问得到的废话输出**：
  > “一、加强领导，提高认识；二、加大巡逻力度，保障交通安全；三、多部门联合执法，宣传教育为主……”（全是空话，根本没法派警落地！）

  【任务】请制定一份《星光夜市夜间交通排堵与治安防控微改造联勤实战方案》。
  【输出格式】请用 Markdown 表格输出，包含四列：【痛点靶向】【具体管控措施（精确到时段与物理隔离手段）】【警力与联勤配置（交警/派出所/城管/物业）】【突发预案触发阈值与处置动作】。

  | :--- | :--- | :--- | :--- |
  | **1. 地铁3号口外卖/网约车违停锁死主路** | ① **物理硬隔离**：每晚 18:30-23:30，在地铁3号口左右50米设置水马与反光锥，封闭机非混行开口；<br>② **远端即停即走点**：在距离夜市入口 120 米的支路划定“网约车/外卖临时蓄车区（限时停靠3分钟）”，通过电子围栏协调平台导航偏移。 | **交警**：1警+2辅（驻守地铁口北侧分流点）；<br>**电子警察**：开启违停球机 3 分钟自动抓拍提醒。 | **阈值**：排队缓行尾部倒灌至主干道交叉口。<br>**动作**：交警立即对支路实施“只出不进”单向循环管控，引导社会车辆绕行次干道。 |

### 模块三：城市交通排堵与社会面治安智能监控实战（20 分钟）

在公安技术部门与交警/治安日常工作中，监控与交通管理有三大高频提效点，下面逐一拆解：

#### 实战剧本 1：多模态视觉大模型（VLM）对传统监控告警的“二次智能复核”（降误报神器）
* **业务痛点**：分局视频专网里原有的传统算法（如烟火检测、人员聚集检测、违停检测）每天产生上万条告警，其实 80% 是误报（比如把晚霞识别成火情、把等红灯的行人识别成非法聚集、把环卫作业车当成违停），图侦辅警每天点鼠标消警点到手软。
* **AI 解决方案**：让传统小模型先抓拍告警图片，再调用**本地多模态视觉大模型（如 Qwen2.5-VL）**自动看图复核，用结构化提示词过滤掉假告警，只把真正高风险的告警推给指挥台。
* **📋 可直接复制的【多模态监控复核系统提示词（System Prompt）】**：
  ```markdown
  你是一名公安视频巡检智能复核员。请仔细观察输入的街面监控抓拍图片及传统算法给出的初步标签，结合画面上下文语义进行二次研判。
  请重点区分以下常见误报情形：
  1. 若初步标签为【人员异常聚集】：请观察人群是否处于公交站台候车、斑马线等待绿灯或正常排队购物。若是正常秩序，判定为误报（is_false_alarm: true）；若存在推搡、围观争吵、拉横幅或堵塞机动车道，判定为真实告警（is_false_alarm: false）。
  2. 若初步标签为【占道违停/堵塞通道】：请观察车辆是否为正在作业的警车、消防车、救护车或环卫清运车。若是特种作业车辆，判定为误报；若是社会车辆/非机动车堵塞消防通道或人行盲道，判定为真实告警。
  3. 请严格输出纯 JSON 格式，字段如下：
  {
    "camera_id": "摄像头编号",
    "original_tag": "传统算法原标签",
    "is_false_alarm": true或false,
    "risk_level": "高/中/低/无",
    "scene_description": "50字以内客观描述画面中的人、车、行为特征",
    "disposal_suggestion": "无需处置 或 建议推送[交警/治安/城管]进行[具体动作]"
  }
  ```

#### 实战剧本 2：用“表头代写法”生成路口交通流量诊断与信号灯配时优化脚本
* **业务痛点**：技术科或交警研判室从卡口导出了全区 20 个重点路口一周的每 15 分钟过车流量与平均车速 CSV 表（几万行），想找出**“哪个路口在哪个时段发生了流量未饱和但车速暴跌（说明绿信比不合理或下游溢流锁死）”**，手工做 Excel 透视表要半天。
* **📋 可直接发给 AI 的【表头代写脚本提示词】**：
  ```markdown
  【角色】你是一名精通交通工程学与 Python 数据处理的公安科信工程师。
  【背景与约束】我本地有一份卡口交通流导出文件 `mock_traffic_flow.csv`，由于公安内网环境限制，不能安装第三方库（请仅使用 Python 3 标准库 `csv`, `collections`, `statistics` 编写，确保零依赖直接运行）。
  【任务与表头结构】CSV 包含以下字段：
  `intersection_id`（路口编号）, `intersection_name`（路口名称）, `direction`（进口方向：东向西/西向东/南向北/北向南）, `time_slot`（时段，如 07:30-07:45）, `vehicle_count`（15分钟过车数）, `Saturation_limit`（该方向15分钟设计通行能力上限）, `avg_speed_kmh`（平均车速 km/h）, `heavy_truck_ratio`（大型车占比）。
  请编写一段 Python 脚本，自动分析并打印出：
  1. 【极度拥堵时段黑榜】：计算各路口方向的饱和度（vehicle_count / Saturation_limit），找出饱和度 > 0.90 且平均车速 < 15 km/h 的高危拥堵记录；
  2. 【配时失衡诊断（绿灯空放 vs 红灯排队）】：找出同一路口、同一时段下，某方向饱和度 > 0.95（严重排队），但相交垂直方向饱和度 < 0.35（绿灯空放）的路口与时段，自动给出“建议将低饱和方向绿灯时长核减 8~12 秒补偿给高饱和方向”的配时优化建议！
  ```
  *(注：这段提示词生成的零依赖 Python 脚本已经为你内置在 `labs/session1_traffic_monitor/analyze_traffic_and_alerts.py` 中，待会儿后 15 分钟直接运行体验！)*
