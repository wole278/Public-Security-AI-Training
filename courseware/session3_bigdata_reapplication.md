### 模块一：唤醒沉睡的 110 警情——非结构化文本打标与“防民转刑”预警（16 分钟）

#### 1. 警务大数据沉睡的最大痛点
分局指挥中心和科信部门存着成百上千万条历史 110 接处警工单，但除了“报警时间、派出所管段、警情大类（纠纷/求助/盗窃）”是标准字段外，最有价值的**《接警简要案情》和《处警反馈结果》全是一大段人工手打的自由文本**，例如：
> *“报警人张某称在XX路XX弄X号X室与前夫李某因抚养费及房产分割发生激烈争吵，李某喝了酒扬言要同归于尽，现场有推搡，民警到场已劝开。”*

传统数据库查询（`SELECT ... WHERE`）对这种自由文本束手无策，导致**同一个家庭或邻里在半年内报警 4 次、矛盾一步步从“口角”升级到“饮酒推搡”再到“持刀威胁”**，却因为每次接警员归类不同（有时归“家庭纠纷”、有时归“噪音扰民”、有时归“求助”），没能触发预警，极易酿成“民转刑”恶性命案！

#### 2. AI 破局之道：批量文本结构化打标 + 多维风险赋分算法
我们可以用两种方式激活这批沉睡数据：
* **方式 A（内网已部署本地大模型 API）**：写一段循环脚本，把每天新增的 110 警情文本喂给内网本地大模型（Qwen/DeepSeek），让它强制输出结构化标签 JSON。
* **方式 B（内网无显卡/纯 CPU 办公电脑）**：让 AI 帮我们编写一套**“高危风险特征词库 + 同地址/同手机号时空聚合评分”**的零依赖 Python 脚本，10 秒扫完十万条历史警情！

#### 📋 可直接复制的【110 非结构化警情批量结构化提取提示词】
```markdown
【角色】你是一名公安指挥中心情指行一体化研判专家。
【背景与约束】请对输入的 110 接处警《简要案情与处警反馈》文本进行深度语义解析，重点识别可能引发“民转刑”命案或个人极端事件的高危苗头。严格依据文本提取，不主观编造。
【任务与输出格式】请输出纯 JSON 数组，每条警情提取以下 7 个结构化字段：
- `call_id`: 工单编号
- `dispute_subtype`: 细分矛盾类型（枚举：婚恋情感 / 家庭房产遗产 / 邻里噪音漏水 / 劳资欠薪 / 消费退费 / 债务借贷 / 其他）
- `high_risk_flags`: 提取文中的高危风险标签数组（如：["涉酒", "扬言报复/同归于尽", "持械/刀具", "肢体冲突", "夜间22点后", "涉及精神异常/弱势群体"]）
- `escalation_score`: 矛盾烈度评分（1~10分，出现持械或扬言行凶直接评 9~10 分）
- `standardized_address`: 归一化后的标准地址（精确到弄/号/室，便于跨工单聚合碰撞）
- `followup_action`: 建议推送部门与跟进等级（如：“【红色一级预警】立即推送社区民警+司法所+居委24小时内上门联合排摸，落实一人一档”）
```

#### 🔍 真实效果预览（当 AI + 聚合脚本扫过全区 110 工单后）：
原本散落在 3 个月里的 4 条普通工单被瞬间串联高亮：
* `10月02日` [噪音求助] XX弄12号301室（烈度 2分）→ `10月15日` [邻里口角] XX弄12号301与401室（烈度 4分，含“推搡”）→ `10月28日` [纠纷] XX弄12号楼道（烈度 7分，含“饮酒、砸门”）→ `11月03日` [纠纷] XX弄12号301室（烈度 9分，含“扬言拿菜刀拼命”）。
* **系统自动弹出【红色一级防民转刑预警】**：直接挽救一起潜在恶性案件！

### 模块二：Text-to-SQL 自然语言问数——把大白话变成复杂数据库查询（14 分钟）

#### 1. 痛点还原
业务大队（刑侦、交警、治安）经常临时向技术科或研判员提复杂统计需求：
> *“今晚局领导开会急用：帮我查一下今年第3季度，全区各派出所辖区在每周五、周六晚 20:00 至次日凌晨 02:00 之间，发生在酒吧/KTV/夜市周边的寻衅滋事和殴打他人警情数量，还要算出跟去年同期的同比涨跌幅，按涨幅从高到低排前 5 名！”*

这种查询涉及**时间截取、星期转换、多条件模糊匹配、跨年度同比关联计算（CTE 窗口函数）**，普通技术员手写 SQL 极易写错或漏算。

#### 2. Text-to-SQL 标准三步法（只给表结构，大白话出 SQL）
只需要把内网数据库的**表名和字段名说明（Schema）**粘给 AI，然后直接把领导的原话粘进去！

#### 📋 可直接复制的【警务大数据 Text-to-SQL 万能提示词模板】
```markdown
【角色】你是一名精通 PostgreSQL / Oracle 数据库的公安大数据高级工程师。
【背景与约束】请根据下方提供的警务数据库表结构（脱敏 Schema），将我的业务统计需求转化为高效、准确的 SQL 查询语句。要求：1. 妥善处理除零异常（NULLIF）；2. 关键逻辑处加上中文注释；3. 同时兼容标准 SQL 语法。
【数据库表结构 Schema】：
表名：`t_110_alarm_records`（110接处警主表）
- `alarm_id` VARCHAR: 警情编号（主键）
- `station_name` VARCHAR: 管辖派出所名称
- `alarm_time` TIMESTAMP: 报警时间
- `alarm_category` VARCHAR: 警情细类（如：'殴打他人', '寻衅滋事', '盗窃电瓶', '电信诈骗'）
- `location_type` VARCHAR: 发案部位类型（如：'酒吧KTV', '夜市排档', '居民小区', '道路路口'）
- `brief_case` TEXT: 简要案情描述
- `caller_phone` VARCHAR: 报警人电话（已脱敏）
- `standard_addr` VARCHAR: 标准地址

【我的查询需求】：
统计 2026年第3季度（7月1日至9月30日），各派出所辖区在“周五、周六夜间（20:00至次日02:00）”、发案部位为“酒吧KTV”或“夜市排档”的“殴打他人”及“寻衅滋事”警情总数，并与 2025年第3季度同期同口径数据进行对比，计算同比增幅百分比，按同比增幅降序排列取前 5 名派出所。
```

#### ✅ AI 秒级生成的 SQL 成品（带防除零保护与跨夜时段精准截取）：
```sql
WITH filtered_alarms AS (
    SELECT 
        station_name,
        EXTRACT(YEAR FROM alarm_time) AS alarm_year,
        alarm_id
    FROM t_110_alarm_records
    WHERE alarm_category IN ('殴打他人', '寻衅滋事')
      AND location_type IN ('酒吧KTV', '夜市排档')
      -- 筛选第3季度（7-9月）
      AND EXTRACT(MONTH FROM alarm_time) BETWEEN 7 AND 9
      AND EXTRACT(YEAR FROM alarm_time) IN (2025, 2026)
      -- 筛选周五(5)、周六(6)晚20-24点，或周六(6)、周日(0)凌晨0-2点（即周五周六跨夜）
      AND (
          (EXTRACT(DOW FROM alarm_time) IN (5, 6) AND EXTRACT(HOUR FROM alarm_time) >= 20)
          OR
          (EXTRACT(DOW FROM alarm_time) IN (6, 0) AND EXTRACT(HOUR FROM alarm_time) < 2)
      )
),
yearly_stats AS (
    SELECT 
        station_name,
        COUNT(CASE WHEN alarm_year = 2026 THEN 1 END) AS cnt_2026_q3,
        COUNT(CASE WHEN alarm_year = 2025 THEN 1 END) AS cnt_2025_q3
    FROM filtered_alarms
    GROUP BY station_name
)
SELECT 
    station_name AS "管辖派出所",
    cnt_2026_q3 AS "2026Q3周末夜宵档打架警情数",
    cnt_2025_q3 AS "2025Q3同期警情数",
    ROUND(
        (cnt_2026_q3 - cnt_2025_q3) * 100.0 / NULLIF(cnt_2025_q3, 0), 
        2
    ) AS "同比增幅(%)"
FROM yearly_stats
WHERE cnt_2026_q3 > 0
ORDER BY "同比增幅(%)" DESC NULLS LAST
LIMIT 5;
```
> 💡 **自读感悟**：注意看 AI 处理“周五、周六晚 20:00 至次日凌晨 02:00”的细节——它自动想到了**周六凌晨 0-2 点在日历上属于周六，而周日凌晨 0-2 点属于周六晚上的延续**！这就是把业务规则交给 AI 写 SQL 的降维打击。

#### 2. 技术科特别加餐：如何用 1 台显卡工作站在公安内网搭建私有大模型？
如果技术科想把这套能力**100% 搬进公安内网**，彻底解决真实敏感数据（真笔录、真警情、真流水）直接上 AI 的问题，只需以下**三步极简离线架构**（详见 `handouts/intranet_llm_deployment_guide.md`）：
1. **底层推理引擎**：在内网带 GPU（如 RTX 4090 24G 或双卡）的工作站上离线安装 `Ollama`，导入离线模型权重包 `Qwen2.5-14B-Instruct`（文字与代码全能）+ `Qwen2.5-VL-7B`（监控看图复核）。
2. **警务交互前端与知识库（RAG）**：使用离线 Docker 镜像部署 `OpenWebUI` 或 `Dify`，将《刑法》《治安管理处罚法》《道路交通安全法》《上海公安办案规范》PDF 拖入本地知识库。
3. **全分局共享**：开启内网局域网端口，全分局民警打开内网浏览器输入 `http://内网IP:3000` 即可像用外网大模型一样安全使用，**数据 100% 留在分局机房机柜内**！
